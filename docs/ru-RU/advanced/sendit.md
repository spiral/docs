# Продвинутые возможности — Отправка почты

Spiral предоставляет простой API для электронной почты, основанный на компоненте symfony/mailer.

> **Примечание**
> Компонент доступен по умолчанию в [пакете приложения](https://github.com/spiral/app).

Электронные письма доставляются через "транспорт". Из коробки вы можете доставлять электронные письма через SMTP, настроив DSN в вашем файле `.env` (параметры user, pass и port являются опциональными).

## Установка

Чтобы включить компонент, вам необходимо добавить класс `Spiral\SendIt\Bootloader\MailerBootloader` в список bootloaders.

:::: tabs

::: tab Использование метода

```php app/src/Application/Kernel.php
public function defineBootloaders(): array
{
    return [
        // ...
        \Spiral\SendIt\Bootloader\MailerBootloader::class,
        // ...
    ];
}
```

Подробнее о bootloaders читайте в разделе [Framework — Bootloaders](../framework/bootloaders.md).
:::

::: tab Использование константы

```php app/src/Application/Kernel.php
protected const LOAD = [
    // ...
    \Spiral\SendIt\Bootloader\MailerBootloader::class,
    // ...
];
```

Подробнее о bootloaders читайте в разделе [Framework — Bootloaders](../framework/bootloaders.md).
:::

::::

Этот bootloader настраивает базовые привязки, настройки по умолчанию и очередь для отправки электронных писем. Он также автоматически регистрирует `Spiral\SendIt\Bootloader\BuilderBootloader`, который регистрирует компонент `spiral/views` и предоставляет возможность создавать шаблоны электронных писем с использованием шаблонизатора **Stempler**.

## Конфигурация

:::: tabs

::: tab Переменные окружения
Вы можете настроить компонент через переменные `.env`:

```dotenv
MAILER_DSN=smtp://username:password@example.com:25
MAILER_FROM=John Smith

MAILER_QUEUE_CONNECTION=roadrunner
MAILER_QUEUE=emails
```

:::

::: tab Файл конфигурации
Вы также можете настроить компонент через файл `app/config/mailer.php`.

Вот пример файла конфигурации:

```php
return [
    /**
     * -------------------------------------------------------------------------
     *  Настройка транспорта
     * -------------------------------------------------------------------------
     *
     * MAILER_DSN не является реальным адресом: это удобный формат, который передает большую часть работы по конфигурации почтовику.
     * Поддерживаемые форматы совместимы с компонентом symfony/mailer.
     */
    'dsn' => env('MAILER_DSN'),

    /**
     * -------------------------------------------------------------------------
     *  От кого
     * -------------------------------------------------------------------------
     *
     * Вместо вызова ->from() для каждого создаваемого Email, вы можете настроить это значение глобально.
     */
    'from' => env('MAILER_FROM'),

    /**
     * -------------------------------------------------------------------------
     *  Настройка подключения к очереди
     * -------------------------------------------------------------------------
     *
     * Этот раздел позволяет настроить `queue` и `driver` для отправки электронных писем.
     * `queueConnection` со значением `sync` позволяет отправлять электронные письма без использования очереди.
     */
    'queue' => env('MAILER_QUEUE'), // не будет использоваться для синхронной очереди
    'queueConnection' => env('MAILER_QUEUE_CONNECTION', 'sync'),
];

```

### DSN

Параметр `MAILER_DSN` используется для настройки транспорта для доставки электронных писем. Компонент использует компонент `symfony/mailer` для отправки электронных писем и поддерживает несколько встроенных транспортов, включая `SMTP`, `sendmail` и функцию PHP `mail()`.

> **Примечание**
> DSN (Data Source Name) — это строка, которая указывает используемый транспорт и может включать такие параметры, как пользователь, пароль и порт. Вот пример: `smtp://username:password@example.com:25`

| Протокол DSN | Пример                                 | Описание                                                                                                                                                                                                                                      |
|--------------|----------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| smtp         | `smtp://user:pass@smtp.example.com:25` | Mailer использует SMTP-сервер для отправки электронных писем                                                                                                                                                                                     |
| sendmail     | `sendmail://default`                   | Mailer использует локальный двоичный файл sendmail для отправки электронных писем                                                                                                                                                                |
| native       | `native://default`                     | Mailer использует двоичный файл sendmail и параметры, настроенные в настройке `sendmail_path` файла `php.ini`. На хостах Windows Mailer возвращается к настройкам `smtp` и `smtp_port` `php.ini`, когда `sendmail_path` не настроен. |

> **Примечание**
> Вы можете найти больше информации о различных типах транспортов, поддерживаемых компонентом `symfony/mailer`, и о том, как их настроить, в официальной [документации Symfony](https://symfony.com/doc/current/mailer.html#using-built-in-transports)

### Пользовательский транспорт почты

В дополнение к встроенным транспортам, поддерживаемым компонентом `symfony/mailer`, Spiral также позволяет использовать пользовательские транспорты.

Чтобы использовать пользовательский транспорт, вам нужно будет создать класс, который реализует `Symfony\Component\Mailer\Transport\TransportInterface`, который является частью компонента `symfony/mailer`. Этот класс должен обрабатывать логику отправки электронного письма с использованием желаемого транспорта.

Предположим, у вас есть несколько DSN транспортов, и вы хотите использовать алгоритм Round Robin для выбора одного из них для отправки электронных писем.

Вот пример того, как использовать пользовательский транспорт:

```php
use Spiral\Boot\Bootloader\Bootloader;
use Symfony\Component\Mailer\Transport\TransportInterface;
use Symfony\Component\Mailer\Transport\RoundRobinTransport;
use Symfony\Component\Mailer\Transport;

class AppBootloader extends Bootloader
{
    protected const DEPENDENCIES = [
        \Spiral\SendIt\Bootloader\MailerBootloader::class,
    ];
    
    protected const SINGLETONS = [
        TransportInterface::class => [self::class, 'initTransport'],
    ];
    
    public function initTransport(): TransportInterface
    {
        $transports = [];
        
        $dsns = [
            'smtp://...',
            'smtp://...',
            // ...
        ];

        foreach($dsns as $dsn) {
            $transports[] = Transport::fromDsn($dsn);
        }

        return new RoundRobinTransport($transports);
    }
}
```

> **Примечание**
> Важно отметить, что создание и настройка пользовательских транспортов может быть сложной и может потребовать глубокого понимания компонента Symfony Mailer и его интерфейса Transport

### Очередь

Отправка электронных писем может быть трудоемкой задачей, и если ваше приложение отправляет большое количество электронных писем, это может замедлить общую производительность вашего приложения. Один из способов смягчить эту проблему — использовать задачи очереди для отправки электронных писем.

<details>
    <summary>Нажмите, чтобы показать преимущества использования задач очереди для отправки электронных писем</summary>

- **Улучшенная производительность:** Перекладывая задачу отправки электронных писем на задачу очереди, вы можете предотвратить блокировку основного приложения во время ожидания отправки электронного письма. Это может улучшить общую производительность вашего приложения.
- **Масштабируемость:** Если вашему приложению нужно отправлять большое количество электронных писем, использование задачи очереди позволяет масштабировать количество рабочих процессов для обработки нагрузки, не влияя на производительность основного приложения.
- **Механизм повтора:** Если при отправке электронного письма возникает ошибка, задача может быть настроена на повтор позже или после определенного количества попыток. Это может быть полезно для обработки временных сбоев, например, когда почтовый сервер недоступен.
- **Приоритизация:** В зависимости от приоритета электронного письма вы можете сортировать очередь и обрабатывать наиболее важные электронные письма в первую очередь.
- **Логирование:** Задача очереди предоставляет механизм ведения журнала для отслеживания статуса электронных писем (отправлено, не удалось, повтор).

</details>

Spiral предоставляет простой способ настройки подключения к очереди и конвейера для отправки электронных писем.

В файле `.env` вы можете настроить подключение к очереди и конвейер для использования при отправке электронных писем, установив переменные `MAILER_QUEUE_CONNECTION` и `MAILER_QUEUE`.

Вы также можете настроить очередь электронных писем в файле конфигурации `app/config/mailer.php`.

> **Узнать больше**
> Подробнее о конфигурации подключения к очереди читайте в разделе [Queue — Installation and Configuration](../queue/configuration.md).

## Использование

Компонент предоставляет возможность создавать богатые по содержанию шаблоны электронных писем с использованием представлений `Stempler`:

```html

<extends:sendit:builder subject="I'm afraid I can't do that"/>
<use:bundle path="sendit:bundle"/>

<email:attach path="{{ $attachment }}" name="attachment.txt"/>

<block:html>
    <p>I'm sorry, {{ $name }}!</p>
    <p>
        <email:image path="path/to/image.png"/>
    </p>
</block:html>
```

Для использования:

```php
use Spiral\Mailer\MailerInterface;
use Spiral\Mailer\Message;

public function send(MailerInterface $mailer): void
{
    $mailer->send(new Message(
        'template.dark.php', 
        'email@domain.com',
        [
            'name' => 'Dave',
            'attachment' => __FILE__,
        ]
    ));
}
```

### Отправка сообщений с задержкой

Компонент позволяет отправлять сообщения с задержкой. Время задержки устанавливается с помощью метода `setDelay`:

```php
use Spiral\Mailer\Message;

$message = new Message('test', 'email@domain.com');
$message->setDelay(new \DateTimeImmutable('+ 60 minute'));
// или
$message->setDelay(new \DateInterval('PT60S'));
// или
$message->setDelay(100);
```

## Пользовательский почтовый транспорт

В некоторых случаях вам может потребоваться использовать пользовательскую почту, которая не предоставляется компонентом `symfony/mailer`. В этом случае вы можете зарегистрировать пользовательский транспорт, используя интерфейс `Spiral\SendIt\TransportRegistryInterface`.

```php
use Spiral\Boot\Bootloader\Bootloader;
use Spiral\SendIt\TransportRegistryInterface;
use Symfony\Component\Mailer\Transport\c;

class AppBootloader extends Bootloader 
{
    public function boot(TransportRegistryInterface $registry): void
    {
        $registry->registerTransport(new SendmailTransportFactory(...));
    }
}
```
