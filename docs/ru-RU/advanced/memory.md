# Продвинутые возможности — Статическая память

Фреймворк (компонент `spiral/boot`) предоставляет удобный интерфейс для хранения данных вычислений, разделяемых между процессами.

> **Примечание**
> Текущая реализация разделяемой памяти хранит данные в физических файлах с помощью OpCache. Будущие реализации переместят хранение данных в RoadRunner или разделяемое PHP расширение с SHM, не привязывайте вашу кодовую базу к физическим файлам.

## MemoryInterface

Используйте интерфейс `Spiral\Boot\MemoryInterface` для хранения результатов вычислений:

```php
/**
 * Долговременный кэш памяти. Используйте это хранилище для запоминания результатов ваших вычислений, 
 * не храните пользовательские или не-статические данные здесь (!).
 */
interface MemoryInterface
{
    /**
     * Чтение данных из долговременного кэша памяти. Должен возвращать точно такое же значение, 
     * как было сохранено, или null. Текущее соглашение позволяет хранить сериализуемые 
     * (var_export-able) данные.
     *
     * @param string $section Не чувствительно к регистру.
     * @return string|array|null
     */
    public function loadData(string $section);

    /**
     * Поместить данные в долговременный кэш памяти. Внутренние ссылки или замыкания не допускаются. 
     * Текущее соглашение позволяет хранить сериализуемые (var_export-able) данные.
     *
     * @param string       $section Не чувствительно к регистру.
     * @param string|array $data
     */
    public function saveData(string $section, $data);
}
```

## Случаи использования

Общая идея памяти — ускорить приложение путем кэширования результата выполнения некоторой функциональности. Компонент памяти используется для хранения кэша конфигурации, схем ORM и ODM, списка консольных команд и кэша токенизатора. Он также может использоваться для кэширования скомпилированных маршрутов и т.д.

> **Примечание**
> Память приложения никогда не должна использоваться для хранения пользовательских данных.

## Практический пример

Давайте рассмотрим пример сервиса, используемого для анализа доступных классов для вычисления некоторого поведения (операций):

```php
abstract class Operation
{
    /**
     * Выполнить некоторую операцию.
     */
    abstract public function perform(mixed $request): void;
}

class OperationService
{
    /**
     * Список операций, связанных с их классом.
     * @var class-string[] 
     */
    protected array $operations = [];

    public function __construct(
        MemoryInterface $memory, 
        ClassesInterface $classes
    ) {
        $this->operations = $memory->loadData('operations');

        if (\is_null($this->operations)) {
            $this->operations = $this->locateOperations($classes); // медленная операция
            $memory->saveData('operations', $this->operations);
        }      
    }

    public function run(string $operation, mixed $request): void
    {
        // Выполнить операцию на основе свойства $operations
    }

    /**
     * @return class-string[]
     */
    protected function locateOperations(ClassesInterface $classes): array
    {
        // Сгенерировать список доступных операций путем сканирования каждого доступного класса
    }
}
```

> **Примечание**
> В настоящее время вы можете хранить в памяти только массивы или скалярные значения.

Вы можете реализовать свою версию `Spiral\Boot\MemoryInterface`, используя APC, XCache, DHT на RoadRunner, Redis или даже Memcache.

Прежде чем встроить `Spiral\Boot\MemoryInterface` в ваш компонент или сервис:

* Не храните никаких данных, связанных с пользовательским запросом, действием или информацией. Память предназначена только для кэширования логики
* Предполагайте, что память может исчезнуть в любой момент
* `saveData` является потокобезопасным, но замедляется при более высокой конкуренции
* `saveData` более дорогостоящий, чем `loadData`, убедитесь, что ничего не сохраняете в памяти во время выполнения приложения
* [загрузчики (bootloaders)](../framework/bootloaders.md) и [команды](../console/commands.md) — лучшие места для использования памяти
