# Контейнер — Атрибуты

Spiral предоставляет набор атрибутов, которые можно использовать для обеспечения дополнительного контроля над разрешением зависимостей:

## Singleton

Использование атрибута `#[Singleton]` может быть удобным в ситуациях, когда мы хотим убедиться, что создается и используется только один экземпляр класса во всем приложении, например, с менеджерами конфигурации, соединениями с базой данных или логгерами.

#### Пример

Предположим, у вас есть менеджер конфигурации в вашем приложении, который читает из файла конфигурации и предоставляет доступ к различным настройкам конфигурации. Было бы расточительно перезагружать и разбирать файл конфигурации каждый раз, когда вам нужно получить доступ к настройке. Использование атрибута #[Singleton] гарантирует, что после загрузки и разбора файла конфигурации он остается в памяти на протяжении всего жизненного цикла приложения.

```php
use Spiral\Core\Attribute\Singleton;

#[Singleton]
final class ConfigurationManager
{
    private readonly array $config;

    public function __construct()
    {
        $this->config = parse_ini_file('config.ini');
    }

    public function get(string $key)
    {
        return $this->config[$key] ?? null;
    }
}
```

## Scope

Позволяет установить определенную область видимости, в которой может быть разрешена зависимость. Если попытаться разрешить зависимость в другой области видимости, будет выброшено исключение, указывающее на несоответствие области видимости. Этот атрибут помогает обеспечить строгие правила областей видимости и предотвращает ошибочное разрешение зависимостей в непредназначенных областях видимости.

#### Пример

Рассмотрим приложение, где определенные ресурсы или операции ограничены аутентифицированными пользователями. Для таких ресурсов вы захотите:

1. Убедиться, что пользователь аутентифицирован.
2. Сделать данные аутентифицированного пользователя доступными во всем приложении во время текущего запроса.

Этот класс содержит информацию об аутентифицированном пользователе. Эти данные предназначены для доступа и разрешения только когда пользователь аутентифицирован (т.е. в области видимости auth).

```php
use Spiral\Core\Attribute\Scope;

#[Scope('auth')]
final readonly class AuthenticatedUser
{
    public function __construct(
        private int $id,
        private string $name, 
        private string $email,
    ) {
    }
}
```

Посредник проверяет, аутентифицирован ли пользователь. Если да, он настраивает область видимости auth в контейнере IoC и привязывает данные аутентифицированного пользователя к классу AuthenticatedUser.

```php;
use Psr\Http\Server\MiddlewareInterface;
use Psr\Http\Message\ResponseInterface as Response;
use Psr\Http\Message\ServerRequestInterface as Request;
use Psr\Http\Server\RequestHandlerInterface as Handler;

final class AuthMiddleware implements MiddlewareInterface
{
    public function __construct(
        private readonly ContainerInterface $container
    ) {
    }

    public function process(Request $request, Handler $handler): Response
    {
        // Это упрощенная проверка аутентификации.
        // В реальном приложении это может включать проверку данных сессии, JWT токенов и т.д.
        if ($request->hasHeader('Authorization')) {
            // Получить данные пользователя на основе заголовка авторизации. 
            // Для простоты мы здесь жестко кодируем данные пользователя.
            $user = new AuthenticatedUser(1, 'John Doe', 'john.doe@example.com');

            // Настроить область видимости auth
            return $this->container->runScoped(
                closure: function (ContainerInterface $container) use ($next, $request) {
                    // Теперь, в этой области видимости, вы можете получить экземпляр аутентифицированного пользователя.
                    $authenticatedUser = $container->get(AuthenticatedUser::class);
                    
                    // Продолжить обработку запроса.
                    return $handler($request);
                },
                bindings: [AuthenticatedUser::class => $user],
                name: 'auth'
            );

        } else {
            // Заголовок аутентификации не найден.
            // Вернуть ответ о неавторизованности или просто продолжить обработку.
            return $handler($request);
        }
    }
}
```

Допустим, у нас есть контроллер или сервис, который требует данные аутентифицированного пользователя. Пытаясь разрешить класс `AuthenticatedUser` из контейнера, мы можем быть уверены, что либо получаем аутентифицированного пользователя, либо находимся в области видимости auth (благодаря атрибуту #[Scope('auth')]).

```php
final class UserProfileController
{
    public function getProfile(AuthenticatedUser $user)
    {
        // Использовать данные $user для получения и возврата профиля.
    }
}
```

> **Примечание**
> Подробнее об областях видимости контейнера читайте в разделе [Фреймворк — Области видимости IoC](../framework/scopes.md).

## Finalize

Позволяет определить метод финализации для класса. Когда зависимость разрешается в области видимости, и эта область видимости уничтожается, будет вызван метод финализации, указанный этим атрибутом. Цель метода финализации состоит в выполнении любых необходимых действий по очистке или финализации перед уничтожением области видимости. Этот атрибут предоставляет удобный способ обработки очистки ресурсов и обеспечения правильного уничтожения объектов, когда область видимости больше не нужна.

#### Пример

Представьте, что вы работаете с соединением с базой данных. После завершения работы с ним, особенно в определенной области видимости, вы можете захотеть закрыть соединение или освободить другие ресурсы.

```php
use Spiral\Core\Attribute\Finalize;

#[Finalize(method: 'closeConnection')]
final class DatabaseConnection
{
    private $connection;

    public function __construct()
    {
        // Инициализировать соединение с базой данных
    }

    public function query($sql)
    {
        // Выполнить запрос к базе данных
    }

    public function closeConnection(): void
    {
        // Закрыть соединение
    }
}
```

При использовании этого класса в области видимости, после завершения области видимости будет вызван метод closeConnection, обеспечивая освобождение ресурсов:

```php
$container->runScoped(
    closure: function (DatabaseConnection $db) {
        // Выполнить некоторые операции с базой данных
        $users = $db->query('SELECT * FROM users');
        // ...  
    },
    bindings: [DatabaseConnection::class => new DatabaseConnection()],
);

// После уничтожения области видимости соединение автоматически закрывается.
```

> **Предупреждение**
> Объект может быть утечен, но финализирован. Вам следует избегать таких ситуаций.

```php
$root = new Container();
$obj = $root->get(Foo::class);
unset($root); // Будет вызван финализатор Foo

// Здесь у нас есть утечка финализированного объекта. Это `$obj`.
```

## Комбинирование атрибутов

Все атрибуты — `#[Finalize]`, `#[Singleton]` и `#[Scope]` — полностью совместимы друг с другом. Это означает, что вы можете использовать эти атрибуты одновременно на одном и том же классе, обеспечивая тонкий контроль над поведением и жизненным циклом ваших зависимостей.

#### Пример

Представьте, что у вас есть сервис кэширования, где:

1. Должен быть создан только один экземпляр сервиса кэширования на протяжении всего жизненного цикла приложения (синглтон).
2. Сервис должен быть доступен только в определенных частях вашего приложения, например, при обработке HTTP-запроса (с областью видимости).
3. Когда приложение завершает работу или когда заканчивается область видимости, вы хотите убедиться, что все ожидающие операции кэша (например, обратная запись) финализированы и любые ресурсы (например, открытые дескрипторы файлов или сетевые соединения) закрыты.

```php
namespace App\Services;

use Psr\Log\LoggerInterface;
use Spiral\Core\Attribute\Finalize;
use Spiral\Core\Attribute\Scope;
use Spiral\Core\Attribute\Singleton;

#[Singleton]
#[Scope('http')]
#[Finalize(method: 'shutdown')]
final class CacheService
{
    private array $cache = [];
    public function __construct(
        private readonly LoggerInterface $logger,
    ) {
    }

    public function get(string $key): ?string
    {
        return $this->cache[$key] ?? null;
    }

    public function set(string $key, string $value): void
    {
        $this->cache[$key] = $value;
    }

    public function shutdown(): void
    {
        $this->logger->info("CacheService is finalizing.");
        
        // Сбросить кэш в постоянное хранилище, закрыть любые ресурсы и т.д.
        $this->cache = [];
    }
}
```
