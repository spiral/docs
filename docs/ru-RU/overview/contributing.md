# Обзор — Руководство по участию

Заинтересованы в помощи с Spiral? Это проект с открытым исходным кодом, который нуждается в помощи разработчиков, таких как вы, чтобы поддерживать его работу и делать еще лучше. Есть множество способов принять участие.

## Pull Requests

Один из способов внести вклад в фреймворк — отправить pull requests на GitHub. Если у вас есть исправление или улучшение, вы можете отправить [pull request](https://github.com/spiral/framework/pulls), и он будет рассмотрен мейнтейнерами. Есть несколько требований, о которых вы должны знать при создании pull request:

### Объявление строгих типов

Фреймворк требует, чтобы все PHP-файлы объявляли [строгие типы](https://www.php.net/manual/en/language.types.declarations.php#language.types.declarations.strict) с использованием директивы `declare(strict_types=1);` в верхней части файла. Это помогает обеспечить типобезопасность кода и снижает риск ошибок.

Вот пример того, как должна использоваться эта директива:

```php
<?php

declare(strict_types=1);

namespace App;

// ...
```

### Следование стандарту кодирования PSR-12

Убедитесь, что ваш код следует стандарту кодирования [PSR-12](https://www.php-fig.org/psr/psr-12/). Это набор руководящих принципов о том, как код должен быть отформатирован и структурирован, чтобы он был последовательным и легким для чтения.

#### Проверка кода

```terminal
./vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php -vvv --dry-run --using-cache=no
```

#### Автоматическое исправление стиля кода

```terminal
./vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php -vvv --using-cache=no
```

> **Примечание**
> Пакет будет принудительно устанавливать окончания строк `CL`.

### Включение тестов

Важная вещь, которую следует помнить при отправке кода в Spiral — включать тесты. Это помогает убедиться, что код, который вы отправляете, работает так, как должен, и что он не вызывает новых проблем, а также упрощает мейнтейнерам проверку правильности вашего кода.

#### Запуск тестов

```terminal
./vendor/bin/phpunit 
```

### Использование Psalm

Перед отправкой любого кода вы должны использовать [Psalm](https://psalm.dev/) для проверки на наличие ошибок или проблем. Это гарантирует, что ваш код правильный и следует лучшим практикам. Spiral использует уровень ошибок Psalm **"4"** при проверке кода. Это простой шаг, чтобы убедиться, что ваш вклад соответствует стандарту.

#### Запуск Psalm

```terminal
./vendor/bin/psalm --no-cache
```

### Держите это просто

Еще одна вещь, которую следует помнить при участии в Spiral — старайтесь делать ваш код как можно более простым и понятным. Мейнтейнеры предпочитают решения, которые легко понять и реализовать, а не слишком сложные. Поэтому при создании pull request старайтесь думать о самом простом способе решения проблемы и представить его таким образом. Это поможет вашему pull request быть принятым быстрее.

## Проблемы

Если вы столкнулись с какими-либо проблемами или уязвимостями безопасности при использовании Spiral, пожалуйста, сообщите о них. Мейнтейнеры очень серьезно относятся к этим вопросам и сделают все возможное, чтобы решить их как можно скорее. Вы можете сообщить о проблемах или уязвимостях, открыв [issue](https://github.com/spiral/framework/issues) в GitHub-репозитории `spiral/framework`.
