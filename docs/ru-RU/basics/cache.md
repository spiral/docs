# Основы — Кэш

Кэширование — это техника, которая может значительно улучшить производительность приложения за счет хранения часто используемых данных в более быстром носителе данных, таком как память. Это снижает необходимость пересчитывать или извлекать данные из более медленного источника, такого как база данных. Реализуя слой кэширования, приложение может быстро извлекать данные из кэша вместо их пересчета или извлечения из более медленного источника, что может улучшить общее время отклика и снизить нагрузку на более медленный источник.

Компонент `spiral/cache` в Spiral предоставляет упрощенный метод для хранения и извлечения данных. Этот компонент соответствует стандарту [PSR-16](https://www.php-fig.org/psr/psr-16/), что делает его универсальным выбором для разработчиков, знакомых со стандартами PHP.

## RoadRunner: революция в кэшировании

Когда мы говорим о мощи кэширования Spiral, RoadRunner находится в его основе. Вот что вам следует знать о RoadRunner:

- **Написан на Go:** RoadRunner — это скорость и эффективность. Go славится своими блестящими показателями производительности, что делает его естественным выбором для высокооктановых операций.

- **Адаптирован для высокой конкурентности:** Он не просто выполняет задачи; он выполняет их параллельно. Разработанный для выполнения высокопроизводительных задач, он может управлять одновременными операциями без заминок.

- **Разнообразные варианты хранения через плагин Key-Value:** С плагином [Key-Value](https://roadrunner.dev/docs/plugins-kv/) от RoadRunner у вас богатый выбор. Выберите известные решения, такие как Redis Server и Memcached, или идите по пути без сервера с такими вариантами, как хранение в памяти.

- **Не требуются расширения PHP:** Одной из выдающихся особенностей использования RoadRunner является исключение любых расширений PHP для Redis или Memcache. Вместо этого вы напрямую общаетесь с RoadRunner, используя RPC.

## Конфигурация

Для начала разместите файл конфигурации в `app/config/cache.php`. Этот файл служит основным местом для настройки параметров хранения и установки хранилища по умолчанию.

Вот пример того, как может выглядеть ваша конфигурация `cache.php`:

```php app/config/cache.php
use Spiral\Cache\Storage\ArrayStorage;
use Spiral\Cache\Storage\FileStorage;

return [
    /**
     * -------------------------------------------------------------------------
     *  Хранилище по умолчанию
     * -------------------------------------------------------------------------
     * 
     * Ключ одного из зарегистрированных хранилищ кэша для использования по умолчанию.
     */
    'default' => env('CACHE_STORAGE', 'rr-redis'),
    
    /**
     * -------------------------------------------------------------------------
     *  Псевдонимы
     * -------------------------------------------------------------------------
     * 
     * Псевдонимы, если вы хотите использовать доменно-специфичные хранилища.
     */
    'aliases' => [
        'user-data' => 'rr-redis',
        'blog-data' => [
            'storage' => 'rr-redis',
            'prefix' => 'blog_'
        ],
    ],
    
    /**
     * -------------------------------------------------------------------------
     *  Хранилища
     * -------------------------------------------------------------------------
     * 
     * Здесь вы можете определить все «хранилища» кэша для вашего приложения, а также их типы.
     */
    'storages' => [
        'rr-redis' => [
            'type' => 'roadrunner',
            'driver' => 'redis',
        ],

        'rr-local' => [
            'type' => 'roadrunner',
            'driver' => 'local',
        ],
        
        'local' => [
            'type' => 'array',
        ],
        
        'file' => [
            'type' => 'file',
            'path' => directory('runtime') . 'cache',
        ],
    ],
    
    /**
     * -------------------------------------------------------------------------
     *  Псевдонимы для типов хранилищ
     * -------------------------------------------------------------------------
     */
    'typeAliases' => [
        'array' => ArrayStorage::class,
        'file' => FileStorage::class,
    ],
];
```

### Работа с псевдонимами

Псевдонимы — это ваш быстрый способ ссылаться на хранилища кэша. Они упрощают код и делают его более читаемым.

Например, у вас есть хранилище с именем `rr-redis`, и вы предпочитаете ссылаться на него как `user-data` в вашем приложении. Раздел `aliases` поможет вам это сделать!

Более того, вы можете получить хранилище кэша, используя `Spiral\Cache\CacheStorageProviderInterface` по имени псевдонима. Он умно отображается на фактическое хранилище, делая ваш код более аккуратным и управляемым.

### Префиксы ключей кэша:

Префиксы играют ключевую роль при работе с псевдонимами кэша. Они обеспечивают уникальность ваших ключей кэша, защищая от случайных пересечений или конфликтов. Добавляя `prefix` к псевдониму, каждый ключ кэша под этим псевдонимом автоматически наследует этот префикс. Это приводит к структурированной, организованной и бесконфликтной системе кэширования.

Включение префиксов в ваш cache.php выполняется просто:

```php app/config/cache.php
return [
    // ...

    'aliases' => [
        'user-data' => [
            'storage' => 'rr-redis',
            'prefix' => 'user_'
        ],
    ],
];
```

В приведенном выше примере любой ключ кэша под псевдонимом `user-data` будет автоматически префиксирован `user_`. Таким образом, ключ кэша типа `profile` будет сохранен как `user_profile`.

## Использование

Компонент кэша Spiral позволяет работать с кэшем, используя два интерфейса: `Psr\SimpleCache\CacheInterface` и `Spiral\Cache\CacheStorageProviderInterface`.

> **Подробнее**
> Вы можете использовать свойства прототипа `cache` и `cacheManager`. Читайте больше о прототипах в разделе [Основы — Прототипирование](../basics/prototype.md).

### Хранилище по умолчанию

Используя `Psr\SimpleCache\CacheInterface`, вы можете получить доступ к хранилищу кэша по умолчанию, которое определено в файле конфигурации. Оно может быть внедрено в класс с помощью внедрения зависимостей, как показано в примере ниже:

```php
namespace App\Service;

use Psr\SimpleCache\CacheInterface;

final class UserService
{
    public function __construct(
        private readonly CacheInterface $cache,
    ) {
    }

    public function find(int $id): User
    {
        // ...
    }
}
```

### Поставщик хранилища кэша

С другой стороны, используя `Spiral\Cache\CacheStorageProviderInterface`, вы можете получить конкретное хранилище по его строковому ключу из файла конфигурации. Это позволяет получить доступ к хранилищу кэша для конкретного домена или случая использования.

```php
namespace App\Service;

use Spiral\Cache\CacheStorageProviderInterface;

class UserService
{
    private readonly CacheInterface $cache;
  
    public function __construct(CacheStorageProviderInterface $provider) 
    {
        $this->cache = $provider->storage('user-data');
    }

    public function find(int $id): User
    {
        //...
    }
}
```

В приведенном примере доменно-специфичное хранилище `user-data` внедряется в класс `UserService`. Это позволяет получить доступ к хранилищу кэша, которое специально адаптировано к потребностям пользовательских данных, и использовать его по всему классу для хранения, извлечения и удаления пользовательских данных из кэша.

Используя этот подход, вы можете легко управлять и поддерживать данные кэша для разных частей приложения и легко переключаться между различными параметрами хранения по мере необходимости.

### Извлечение элементов

Чтобы получить элемент из кэша, вы можете использовать метод `get`. Если элемент не существует, он вернет `null`. Вы также можете указать значение по умолчанию, которое будет возвращено, если элемент не существует.

```php
$data = $this->cache->get('key');

$data = $this->cache->get('key', 'default');
```

Если вам нужно получить несколько элементов одновременно, вы можете использовать метод `getMultiple` и передать массив ключей.

```php
$data = $this->cache->getMultiple(['key', 'other']);
```

### Проверка существования элемента

Если вы хотите проверить, существует ли элемент в кэше, вы можете использовать метод `has`. Он вернет `true`, если элемент существует, и `false`, если нет.

```php
if ($this->cache->has('key')) {
    // ...
}
```

### Сохранение элементов

Чтобы сохранить элемент в кэше, вы можете использовать метод `set`.

```php
$this->cache->set(
    key: 'key', 
    value: ['some' => 'data'], 
    ttl: 3600
);
```

Вы также можете указать, как долго элемент должен храниться (TTL), передав количество `секунд` или объект `DateInterval` или `DateTimeInterface`.

```php
$this->cache->set(
    key: 'key', 
    value: ['some' => 'data'], 
    ttl: \Carbon\Carbon::now()->addHour()
);
```

Если значение не указано, значение кэша будет храниться неопределенно долго (или так долго, как позволяет базовый драйвер хранилища).

```php
$this->cache->set(
    key: 'key', 
    value: ['some' => 'data']
);
```

Вы также можете сохранить несколько элементов одновременно, используя метод `setMultiple` и передав массив пар ключ/значение.

```php
$this->cache->setMultiple(
    values: [
        'key' => ['some' => 'data'], 
        'other' => ['foo' => 'bar']
    ], 
    ttl: 3600
);
```

### Удаление элементов

Если вы хотите удалить элемент из кэша, вы можете использовать метод `delete`.

```php
$this->cache->delete('key');
```

Вы также можете удалить несколько элементов одновременно, используя метод `deleteMultiple` и передав массив ключей.

```php
$this->cache->deleteMultiple(['key', 'other']);
```

### Очистка кэша

Чтобы удалить все элементы из кэша, вы можете использовать метод `clear`.

```php
$this->cache->clear();
```

## Пользовательское хранилище

Компонент позволяет интегрировать [пользовательские методы хранения](https://packagist.org/providers/psr/simple-cache-implementation) через файлы конфигурации, что делает его универсальным и простым в использовании. Таким образом, вы можете использовать любую из доступных реализаций PSR-16.

Для использования пользовательского хранилища вам нужно зарегистрировать его в разделе `storages` файла конфигурации и указать тип хранилища, используя ключ `type`, и любые необходимые параметры конфигурации для этого хранилища.

Вам также нужно будет зарегистрировать класс в разделе `typeAliases` файла конфигурации, чтобы Spiral знал, как создать экземпляр вашего пользовательского хранилища.

## События

| Событие                          | Описание                                                                       |
|----------------------------------|--------------------------------------------------------------------------------|
| `Spiral\Cache\Event\CacheHit`    | Событие будет вызвано при успешном извлечении данных из кэша.                  |
| `Spiral\Cache\Event\CacheMissed` | Событие будет вызвано, если запрашиваемые данные не найдены в кэше.            |
| `Spiral\Cache\Event\KeyDeleted`  | Событие будет вызвано `после` удаления данных из кэша.                         |
| `Spiral\Cache\Event\KeyWritten`  | Событие будет вызвано `после` сохранения данных в кэше.                        |

> **Примечание**
> Чтобы узнать больше о диспетчеризации событий, см. раздел [События](../advanced/events.md) в нашей документации.
